## 第一步：备份签名私钥（最重要，5 分钟）

### 为什么必须做

自动更新强制要求签名验证。私钥一旦丢失，**所有已安装旧版本的用户将永远收不到更新**，只能手动重装。这是不可逆的。

### 你的私钥在这里

```
C:\Users\afire\.tauri\bible-screening.key
```

### 怎么做

1. 按 `Win + E` 打开文件资源管理器
2. 地址栏粘贴：`C:\Users\afire\.tauri\` 回车
3. 找到 `bible-screening.key`（348 字节的那个，**不是** `.pub` 结尾的）
4. 复制它，粘贴到你的**密码管理器**（Bitwarden / 1Password / 微信收藏加密笔记）或**U 盘**
5. 建议改名为 `bible-screening-私钥-勿删.key` 并在备注里写「圣经投影自动更新私钥，丢失则无法发更新」

> `.key.pub` 是公钥，已经写进项目配置了，**不需要备份**，公开的。

## 第二步：推送代码到 GitHub（10 分钟）

代码在我这边已经通过了 `typecheck` 和 `build`。现在要把改动推到 GitHub，这是触发网页版自动部署的前提。

### 方式 A：我帮你执行（推荐）

你直接跟我说「提交并推送」，我来跑 git 命令。**但要注意**：推送需要你的 GitHub 凭据（PAT 或已保存的凭据）。

### 方式 B：你自己在终端执行

打开终端（项目目录 `E:\workspace\bible_screening`），依次执行：

```bash
git add -A
git commit -m "feat: 自动更新 + 网页版部署 + 设置菜单 + 当代译本 + 快捷键"
git push origin main
```

> 如果提示要密码：GitHub 早已不支持账号密码推送，需要用 **Personal Access Token**。
> 生成地址：https://github.com/settings/tokens
> 点 `Generate new token (classic)` → 勾选 `repo` 和 `workflow` → 生成后复制（只显示一次）→ 推送时密码处粘贴这个 token。

### 推送成功后你会看到

访问这个链接能看到最新提交，就说明成功了：
https://github.com/JohnChen30/bible-screening/commits/main

## 第三步：开启 GitHub Pages（网页版上线，5 分钟）

推送代码后，GitHub Actions 会自动开始构建网页版。但**你必须先开启 Pages**，否则部署那一步会失败。

### 具体步骤（带链接）

1. **打开 Pages 设置页**（直接点这个链接）：
   👉 https://github.com/JohnChen30/bible-screening/settings/pages

2. 找到 **"Build and deployment"** 区域 → 下面的 **"Source"** 下拉框

3. 把 Source 从 `Deploy from a branch` 改成 **`GitHub Actions`**

4. 不需要点保存（选完立即生效）

### 然后确认部署状态

1. 打开 Actions 页面：
   👉 https://github.com/JohnChen30/bible-screening/actions

2. 左侧点 **"Deploy Web to GitHub Pages"**

3. 应该能看到一次运行记录。点进去：
   - **绿色勾** = 成功
   - **红色叉** = 失败，点开看哪一步红的，把报错发给我

4. 成功后，网页版地址就是：
   👉 **https://johnchen30.github.io/bible-screening/**

   > 首次部署后可能要等 1-2 分钟才能访问（GitHub 在后台分发文件）。

5. 如果 Actions 里没有运行记录：可能是推送没成功，或者需要手动触发。到 Actions 页面 → 左侧 "Deploy Web to GitHub Pages" → 右侧 **"Run workflow"** 按钮 → 选 `main` → 点绿色 "Run workflow"。

## 第四步：发布桌面版正式包（带自动更新，20 分钟）

这一步产出 `.exe` 安装包 + 签名 + `latest.json`，用户装了它之后就能收到后续更新。

### 4.1 设置签名环境变量

**必须每次新开终端都设一次**（环境变量不持久）。

在 PowerShell 里执行：

```powershell
$env:TAURI_SIGNING_PRIVATE_KEY = "C:\Users\afire\.tauri\bible-screening.key"
```

> 注意：值是这个**文件路径**，Tauri 会自动读取文件内容。

如果之前给私钥设过密码（生成时没设，所以不用管），再加一行：
```powershell
$env:TAURI_SIGNING_PRIVATE_KEY_PASSWORD = "你的密码"
```

### 4.2 打包

在项目根目录 `E:\workspace\bible_screening` 执行：

```powershell
$env:RUSTFLAGS = "--cfg has_std"
npm run tauri build
```

> `RUSTFLAGS` 是这个项目必须的（否则 schemars 编译报错），别漏。
> 打包大约 5-15 分钟，会跑满 CPU。

### 4.3 确认产物

打包完成后，检查这个目录：
```
E:\workspace\bible_screening\src-tauri\target\release\bundle\nsis\
```

应该看到 3 个文件（版本号 0.3.2）：
- `bible_screening_0.3.2_x64-setup.exe` ← 安装包
- `bible_screening_0.3.2_x64-setup.exe.sig` ← 签名
- （如果没看到 `.sig`，说明 4.1 的签名环境变量没设对，回去重做）

### 4.4 生成 latest.json

执行：

```powershell
npm run manifest
```

成功会打印：
```
✓ 已生成 latest.json
  版本: v0.3.2
  安装包: bible_screening_0.3.2_x64-setup.exe
  产物: ...\bundle\latest.json
```

产物位置：`E:\workspace\bible_screening\src-tauri\target\release\bundle\latest.json`

> 想写更新说明可以加参数：
> ```powershell
> npm run manifest -- --notes "新增当代译本、自动更新、网页版"
> ```

### 4.5 创建 GitHub Release 并上传三个文件

1. **打开新建 Release 页面**（直接点）：
   👉 https://github.com/JohnChen30/bible-screening/releases/new

2. 填写：
   - **Choose a tag**：输入 `v0.3.2` → 点下面出现的 **"Create new tag: v0.3.2 on publish"**
     > ⚠️ tag 名字**必须**是 `v0.3.2`（带 v，且和版本号一致），因为更新地址是固定的 `releases/latest/download/latest.json`
   - **Release title**：`v0.3.2`
   - **描述**：随便写本次更新内容

3. **上传附件**：把下面 3 个文件从 `src-tauri\target\release\bundle\` 拖进页面的附件框：
   - `nsis\bible_screening_0.3.2_x64-setup.exe`
   - `nsis\bible_screening_0.3.2_x64-setup.exe.sig`
   - `latest.json`

   > ⚠️ `latest.json` **必须**上传到 Release 附件里，不能只放在仓库文件里。因为更新检查固定请求 `releases/latest/download/latest.json`，这个地址只会指向「最新 Release 的附件」。

4. 确认 **"Set as the latest release"** 是勾选状态

5. 点 **"Publish release"**

### 4.6 上传后立刻验证

浏览器打开这个地址（这是你的用户端会请求的地址）：
👉 https://github.com/JohnChen30/bible-screening/releases/latest/download/latest.json

应该能看到 JSON 内容，类似：
```json
{
  "version": "0.3.2",
  "notes": "Bible Screening v0.3.2",
  "pub_date": "2026-11-08T...",
  "platforms": {
    "windows-x86_64": {
      "signature": "dW50cnVzdGVk...",
      "url": "https://github.com/JohnChen30/bible-screening/releases/download/v0.3.2/bible_screening_0.3.2_x64-setup.exe"
    }
  }
}
```

**能打开就说明自动更新的服务端配置好了。**

## 第五步：验证

### 5.1 验证网页版

打开 👉 https://johnchen30.github.io/bible-screening/

检查：
- 能看到界面（不是白屏）
- 左侧书卷列表能点、经文能显示
- 投影后底部有「打开投影窗口」按钮（网页版专属）

### 5.2 验证桌面版自动更新

⚠️ **第一个能更新的版本，用户必须手动安装一次**（因为旧版本没有 updater 代码）。

所以验证流程是：

1. 先装一个**旧版本**（比如你之前发的 v0.3.0 安装包）
2. 再发一个**新版本**（比如这次的 v0.3.2）
3. 打开旧版本 → 启动时后台检查 → 右下角「设置」左边出现「更新」按钮
4. 点「更新」→ 自动下载安装 → 自动重启 → 变成新版本

如果你现在装的就是 v0.3.2（最新），那它检查后认为「已是最新」，不会显示更新按钮——这是正常的。

### 5.3 验证设置菜单

桌面版运行后，点右下角「设置」：
- 「快捷键」tab：能改键位、能恢复默认
- 「软件版本」tab：显示 v0.3.2、有「打开 GitHub 仓库」「打开网页版」两个按钮，点了会用系统浏览器打开

## 以后每次发新版本的固定流程

只有 6 步，熟练后 15 分钟：

### ① 改版本号（3 个文件）

| 文件 | 位置 |
|---|---|
| `package.json` | `"version": "0.3.2"` |
| `src-tauri/tauri.conf.json` | `"version": "0.3.2"` |
| `src-tauri/Cargo.toml` | `version = "0.3.2"` |

> `vite.config.ts` 里的版本号已改为自动读 `package.json`，不用手改了。

### ② 提交代码

```bash
git add -A && git commit -m "chore: bump to 0.3.3" && git push origin main
```

### ③ 打包（带签名）

```powershell
$env:RUSTFLAGS = "--cfg has_std"
$env:TAURI_SIGNING_PRIVATE_KEY = "C:\Users\afire\.tauri\bible-screening.key"
npm run tauri build
```

### ④ 生成 latest.json

```powershell
npm run manifest -- --notes "本次更新内容"
```

### ⑤ 发 Release

👉 https://github.com/JohnChen30/bible-screening/releases/new

- tag：`v0.3.3`（新版本号）
- 上传 3 个文件：`exe`、`exe.sig`、`latest.json`
- 勾选 "Set as the latest release"
- Publish

### ⑥ 完成

- 网页版：push 后 Actions 自动更新，无需操作
- 桌面版：旧版本用户启动时会看到「更新」按钮

## 常见问题

### Q：Actions 部署报错 `Get Pages site failed`

**原因**：Pages 没开启。
**解决**：回到 [第三步](#第三步开启-github-pages网页版上线5-分钟)，把 Source 改成 `GitHub Actions`。

### Q：打包报错 `failed to get secret key`

**原因**：签名环境变量没设，或者设的是公钥路径（`.pub`）。
**解决**：确认是 `C:\Users\afire\.tauri\bible-screening.key`（没有 `.pub`），并且是在**同一个终端窗口**里先设变量再执行 `npm run tauri build`。

### Q：打包报错 `E0107` / `schemars` 相关

**原因**：漏了 `RUSTFLAGS`。
**解决**：执行 `$env:RUSTFLAGS = "--cfg has_std"` 后重新打包。

### Q：网页版打开是白屏

**原因**：大概率是 base 路径问题，或者 Pages 还没部署完。
**解决**：等 2 分钟刷新；如果还白屏，打开浏览器 F12 控制台看报错发我。

### Q：更新按钮一直不出现

排查顺序：
1. 确认装的是**旧版本**（比 latest.json 里的版本低）
2. 浏览器打开 https://github.com/JohnChen30/bible-screening/releases/latest/download/latest.json 能访问吗？
3. 桌面版有网络代理吗？WebView2 走系统代理，检查代理设置
4. 打开桌面版 F12（调试版）看控制台有没有 updater 报错

### Q：能不能不用手动发 Release，全自动？

可以，需要再加一个 GitHub Actions workflow（用 `tauri-apps/tauri-action`）。但需要先把私钥传到 GitHub Secrets，且 Windows 打包在 GitHub 上比较慢（10-20 分钟）。**建议先手动跑通一次**，确认整个链路没问题，再考虑自动化。你要的话我可以加。
